# HartBreaker on four-hart BlackParrot

The BlackParrot native simulation entry accepts an ELF generated by HartBreaker
and runs it through the in-tree Difftest-S online session. The production path
loads the independent ELF image, creates four Spike references, checks retirement
and supported scalar memory ordering, and waits for every hart and event source
to finish. A native BSG success message alone is not a Difftest-S Pass.

The target source compatibility patch and configuration live in
`scripts/integrations/hartbreaker/`. They are required integration assets, not a
saved test corpus or a benchmarking harness. No source from a local experiment
directory is required by the following commands.

## Dependencies and source layout

Use sibling checkouts of this repository, the compatible `difftest-s` repository,
and its `Spike` reference implementation. Initialize BlackParrot's pinned
submodules with `git submodule update --init --recursive`. Install a Verilator
version supporting `--binary`, the RISC-V GNU ELF toolchain, and a standalone
Spike executable on `PATH`; the standalone executable is used by HartBreaker's
instruction-generation presimulation. The Difftest-S Spike shared library is
built separately with the `ref` target below.

HartBreaker is pinned to upstream commit
`414d2f52022d7c4a915ef9950ac42bba999a2910` from
`https://github.com/comsec-group/hartbreaker.git`. Its Python environment requires
Python 3.10 or later and `hartattack/requirements.txt`, plus `rich` and
`z3-solver` if not installed by the environment. Use Python 3.11 or later when
installing upstream's exact pinned NumPy 2.2.4 requirements.

For example, set paths for the checkouts and a writable build directory:

```sh
export BP_ROOT=/path/to/black-parrot
export HB_ROOT=/path/to/hartbreaker
export BP_BUILD=/path/to/blackparrot-build

git clone https://github.com/comsec-group/hartbreaker.git "$HB_ROOT"
git -C "$HB_ROOT" checkout --detach 414d2f52022d7c4a915ef9950ac42bba999a2910
python3 -m pip install -r "$HB_ROOT/hartattack/requirements.txt" rich z3-solver
```

The bundled `source.json` records the upstream revision, the adapted source
revision, the patch SHA-256, and the expected content hashes of all changed
HartBreaker source files. `setup.py` applies the patch only to the clean pinned
upstream checkout, or accepts the identical already-installed target. It rejects
unrelated edits and a conflicting existing simulator configuration instead of
overwriting them. The simulator path can name the model that will be built later:

```sh
python3 "$BP_ROOT/scripts/integrations/hartbreaker/setup.py" \
  --hartbreaker "$HB_ROOT" \
  --simulators "$BP_BUILD/simulators" \
  --simulator "$BP_BUILD/model/simsc"
```

The installed configuration declares harts `0,1,2,3`, boot address `0x80000000`,
`rv64imc_zicsr_zifencei`, machine mode, no address translation, and the BlackParrot
CLINT base `0x00300000`. The target uses coherent RAM synchronization and does not
rely on CLINT/MMIO accesses or AMOs for its startup and completion barriers.

## Generate an ELF

Use a separate data directory. `--num-cores 1` selects one host generation worker;
the target's `hartids` configuration determines the four simulated harts.

```sh
export WORKDIR="$HB_ROOT"
export HARTATTACK_SIMULATORS_DIR="$BP_BUILD/simulators"
export HARTATTACK_DATADIR="$BP_BUILD/hartbreaker-output"
export HARTATTACK_BUGDIR="$BP_BUILD/hartbreaker-bugs"
export HARTATTACK_CORES=1
source "$HB_ROOT/scripts/env.sh"
cd "$HB_ROOT/hartattack"
PYTHONHASHSEED=0 python3 main.py blackparrot-fourhart-difftest-s \
  --gensingle 70000 --num-cores 1 --num-bbs 70 \
  --authorize-privileges false --fuzz-mcm --verify-memory-trace dat
```

The output is
`$HARTATTACK_DATADIR/manyelfs/blackparrot-fourhart-difftest-s_70000.elf`.
This command generates the concurrent program and performs the generation's
Spike presimulation; it does not simulate BlackParrot or execute Dat3M. Preserve
the seed, command, configuration, and ELF SHA-256 when reproducing a run. Invoke
`--gensingle` separately for distinct seeds; do not infer seed identity from
`--manyelfs` output names or a separate seed-offset argument.

## Build the reference and run the native session

These commands use the in-tree production bootstrap. No external
`DIFFTEST_S_BOOTSTRAP_SOURCE`, trace replay, or prebuilt test library is needed.

```sh
cd "$BP_ROOT"
make -f Makefile.difftest-s ref \
  DIFFTEST_S_SPIKE_HOME=../Spike \
  DIFFTEST_S_SPIKE_BUILD="$BP_BUILD/spike"

make -f Makefile.difftest-s build.verilator \
  DIFFTEST_S=1 CFG=e_bp_multicore_4_cfg \
  DIFFTEST_S_DIR=../difftest-s DIFFTEST_S_SPIKE_HOME=../Spike \
  DIFFTEST_S_SPIKE_BUILD="$BP_BUILD/spike" DUT_PATH="$BP_BUILD/model"

make -f Makefile.difftest-s sim.verilator \
  DIFFTEST_S=1 CFG=e_bp_multicore_4_cfg \
  DIFFTEST_S_DIR=../difftest-s DIFFTEST_S_SPIKE_HOME=../Spike \
  DIFFTEST_S_SPIKE_BUILD="$BP_BUILD/spike" DUT_PATH="$BP_BUILD/model" \
  SIM_PROG="$HARTATTACK_DATADIR/manyelfs/blackparrot-fourhart-difftest-s_70000.elf"
```

A successful checked run needs exactly one authoritative `[BP-FINAL]` report and
`[Difftest-S] Pass`, four harts with nonzero matching retirement/reference/compare
counts, complete source closure and zero pending work. Inspect the native
simulation result as well; an abort, timeout, native failure, `Incomplete`, or
`Unsupported` is not a checked Pass. The generic startup and completion contract
is described in `docs/difftest-s.md`.

## Supported target and native HartBreaker checking

This target exercises bare scalar RAM instructions, ordinary data fences, and
integer dependencies in the fixed four-hart configuration. The program begins
with an independently specified zero-initialization prefix for integer registers,
uses scalar per-hart epoch barriers, and ends only after all four harts reach the
terminal rendezvous and WFI. The source monitor still requires physical stopping,
memory completion, and delivered event-source closure before final success.

AMO/LRSC, floating point, vector, trap/interrupt, MMIO, virtual-memory, and
FENCE.I/FENCE.TSO coverage are outside this target's current scalar contract.
Selecting a different generator instruction mix does not automatically add the
corresponding checker capabilities. Unsupported events remain explicit.

The patched HartBreaker source also contains a BlackParrot retired-load trace
parser for HartBreaker's own MCM validation. It binds the original generated MCM
load metadata to native retirements and requires complete four-hart closure.
The parser does not use the Difftest-S verdict as a memory-model oracle. The
`SIM_PROG` commands above run the production Difftest-S path; they do not install
Dat3M, implement HartBreaker's complete native `--fuzzsingle` simulator launcher,
or automatically run the independent HartBreaker/Dat3M postprocessing path.
Dat3M invocation and HartBreaker's skipped-step/final-register policies must be
reported separately when that path is used.
